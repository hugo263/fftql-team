## 1. 数据源（全部官方、公开、无需登录）

| 端点 | 用途 |
|---|---|
| `draft.premierleague.com/api/bootstrap-static` | 球员元数据、element_types、fixtures（按 GW 分组的 dict） |
| `fantasy.premierleague.com/api/bootstrap-static/` | GW 状态、球员价格（now_cost）、form、ep_next、xG/xA |
| `draft.premierleague.com/api/league/{id}/details` | 联赛详情、玩家名单、积分榜、h2h 对阵 |
| `draft.premierleague.com/api/draft/league/{id}/transactions` | waiver / 自由签约记录（注意路径：含 `draft/`） |
| `draft.premierleague.com/api/draft/league/{id}/trades` | 玩家之间的直接交易（含多球员交易） |
| `draft.premierleague.com/api/league/{id}/element-status` | 球员归属（owner = entry_id 空间） |
| `draft.premierleague.com/api/entry/{entryId}/event/{gw}` | 玩家某 GW Draft 阵容 picks（无队长机制） |
| `draft.premierleague.com/api/event/{gw}/live` | Draft 球员每轮实际得分（用于 Team of the Week 和交易评价） |
| `fantasy.premierleague.com/api/fixtures/?event={gw}` | 比赛完赛状态（弥补官方 `finished` 标志延迟 1-2 天） |

⚠️ ID 空间注意：
- `standings[].league_entry` ↔ `league_entries[].id`
- `transactions[].entry` / `element-status[].owner` ↔ `league_entries[].entry_id`
- 两个空间通过 `league_entries` 表 join。
- Draft 与经典 FPL 的球员 `id` **不能直接互查**；跨 API 合并必须使用稳定的球员 `code`。
- 下轮阵容以 `element-status.owner` 为准；picks 仅用于保留位置/首发与替补顺序。

| 🔄 交易评估器 | 双侧搜索选球员，按价格/EP/form/PPG/xG+xA/出场/伤病 8 维度对比，给出"占优 / 持平 / 吃亏"建议和原因 |

### 流量后台

- 入口：`/admin`
- 指标：页面浏览量、独立访客、会话、30 分钟活跃、平均停留、跳出率、访问趋势、功能模块、来源、设备、浏览器、访问时段和最近活动。
- 隐私：仅保存服务端 HMAC 匿名访客标识，不保存原始 IP；明显机器人事件从后台指标中排除；事件保留 400 天。
- 登录：生产 `config.json` 使用 `adminPasswordHash`（scrypt）、`adminSessionSecret` 与 `analyticsSalt`；这些字段不得提交到仓库。
- 数据从功能上线后开始累计，无法补回上线前的历史访问。
- v41 顶部固定显示北京时间当天 00:00 至今的 PV / UV，以及所有保留日志中的去重联赛使用数；7/30/90 天只控制下方时段指标与图表。时段窗口统一为包含今天的自然日，PV 与日趋势/小时汇总对齐。
- 联赛使用只计成功加载且渲染工作台后的 `league_use` 事件，服务端核对已有官方联赛快照，不把查询 ID、API 轮询、失败加载或服务器缓存数量当作使用。每日刷新不重复记采用；同联赛多个外部访客仍只计一个联赛。
- 管理员登录或使用已有登录状态访问后台时，服务端给该浏览器签发只用于排除统计的长期 HttpOnly 标记；退出登录仍排除。其他设备需登录一次，后续 IP/UA 变化会继续识别。排除标记不具备后台登录权限，不能代替管理员 cookie。
- 只保存 HMAC 匿名 ID，不存原始 IP。匹配已识别匿名 ID 的历史访问也会从统计中排除；跨设备或标记前网络变化的旧记录无法保证全部追溯。UV 为匿名访客估算，不是注册账户数或精确人数。
- 旧埋点未记录联赛 ID；v42 应用户要求从本站 Nginx 日志推断补录：同一 HMAC(IP|UA) 成功打开工作台后 120 秒内，须成功加载对应联赛数据。排除已识别本人、机器人、失败请求和独立 API 刷新；仅补 `collection-v2.json` 新埋点启用前的记录，不能保证历史完整。
- 历史派生文件 `data/analytics/league-history-v1.json` 与原 JSONL 分开保留，补录不增加 PV / UV；历史成功后台登录或读取统计识别出的匿名身份会追溯剔除本人流量。联赛累计去重，打开次数相加，每行标明历史次数；累计不受 7/30/90 天切换影响。`/discover` 从 v41 起纳入 PV；页面样式和内容不变。
- 补录脚本仅在本站服务器运行：`node scripts/backfill-league-usage.cjs /www/wwwlogs/fpl_weekly.access.log` 默认只预览；确认后加 `--write`。可传多份日志（含 .gz），按稳定 ID 幂等合并并备份旧派生文件；不修改原始日志，不导出原始 IP、UA 或密钥。部署必须保留整个 `data/analytics/`。
- 新依赖：`analytics-report.js`、`analytics-identity.js`、`public/analytics.js`。保留 `data/analytics/collection-v2.json` 和 `internal-visitors.json`，部署时不得用本地预览数据覆盖它们。后台资源、公共埋点及 app.js 引用为 `?v=41`，其他未修改资源保持原版本。

## 7. 自动更新节奏

| 触发条件 | 动作 |
|---|---|
| 服务启动 | 拉取并写入默认联赛快照 |
| 浏览器每 60 秒 GET 快照 | 读取最新状态；保留选中的历史 GW、筛选、阵容和交易标注；隐藏页面暂停，恢复可见时检查 |
| 进行中 GW | 服务端快照 TTL 为 60 秒，刷新战报、积分榜和 TOTW；其他联赛也使用相同策略 |
| 非实时 / 下一 deadline | 常规 TTL 默认 15 分钟；到下一 deadline 强制过期，立即切换新 GW 战报 |
| GW 全部比赛 `finished` | 停止 LIVE 展示，保留本轮结果；官方结算前允许常规刷新修正，结算后缓存固定 Draft 分数 |
| 浏览器右上角「↻ 刷新」 | POST /api/refresh 重建快照；失败保留旧数据和更新时间，不伪造零分 |

时间线分开处理：`meta.reportGw` 是当前战报轮次，`lastFinishedGw` 是最近完赛轮次，`upcomingGw` 是预测目标。例如 GW3 进行中分别为 3 / 2 / 3；GW3 完赛后为 3 / 3 / 4。交易中心在 GW3 进行中标“本轮”，GW4 标“下轮”。

实际得分使用该轮锁定 Draft 首发 XI，不使用交易后的当前阵容，不计队长倍数。官方自动换人仅应用一次（已换位 picks 不重复换人），奖励分已含在 Draft `total_points`。H2H 从唯一对阵重建，避免官方累计值已含本轮时重复累加。官方 `event.finished` 且 `data_checked !== false` 的轮次才使用固定分数缓存。

防守贡献（DEFCON）也已包含在官方 `total_points`，不得另加分。经理详情展示的是最新持有阵容和球员原始分，不能与战报的当轮锁定 XI 积分混为一谈。交易中心的左卡为所选 GW 经理净换入分减净换出分，右卡为引援持有期间累计原始分；二者含替补球员分，不声称是经理首发积分增量。

## 8. 修改联赛

要服务其他联赛，只需修改 `config.json` 的 `leagueId` 字段：

```json
{
  "leagueId": <your_league_id>,
  "leagueName": "<your_league_display_name>",
  "port": 3000,
  "refreshMinutes": 15
}
```

重启服务即可：`systemctl restart fpl-weekly`
